# Адаптация React-админки к C++ API

## Цель и границы

Адаптировать существующий packages/web без новых библиотек и без изменения C++.
Сохранить авторизацию, cookie-сессии, обновление списка и визуальное направление.
Удалить UUID, переименование и скачивание конфигураций из админки.
Docker остаётся многоэтапным: Node/Yarn/Vite только в этапе сборки.

## Подход

Использовать существующие App, PeerRow, CreatePeerForm, LoginForm и Root.
Перенести компонентные стили в CSS Modules, общие значения — в единую тему.
Создать Button, IconButton, Input, Modal и повторно используемое представление
одноразовой ссылки. Для иконок использовать небольшие встроенные SVG.
Переписывание приложения и отдельный frontend-сервер противоречат требованиям.

## Список

Peer соответствует GET /api/peers:
publicKey, name, allowedIps, isAdmin, endpoint (string | null),
latestHandshake (Unix seconds), rx, tx.
Ключ React и идентификатор операций — publicKey.
Показать имя, VPN-IP, администратора, статус, handshake, RX/TX и две иконки.
VPN-IP отображается из allowedIps без маски /32 для одиночного IPv4.
Предлагаемое правило статуса: handshake не старше 180 секунд, время в будущем
не считается подключением. Нулевой handshake означает отсутствие данных.
Время и трафик форматируются на клиенте. Сохранить защиту от устаревших ответов
и текущий список при неудачном обновлении.

## Создание и ссылки

Кнопка «Добавить подключение» открывает модальное окно с именем и кнопками
«Создать», «Отмена». Имя обрезается по краям, допустимо 1–100 символов.
POST /api/peers отправляет JSON { name }. Из ответа нужен publicKey.
После успешного POST сразу обновить список и запросить ссылку через
POST /api/peers/links с { publicKey, ttlSeconds: 86400 }.
Предлагаемый фиксированный TTL — 24 часа; настройки TTL в интерфейсе нет.
В этом же окне показать URL, копирование и закрытие.
При ошибке выпуска ссылки после создания сохранить publicKey и предложить
повторить только выпуск ссылки, не создавать ещё одно подключение.
Не читать и не сохранять privateKey в состоянии интерфейса.

Иконка ссылки открывает такое же окно и использует существующий endpoint.
Копировать через Clipboard API; при недоступности или ошибке показать сообщение
и оставить поле ссылки доступным для ручного копирования.
Удаление: подтверждение, DELETE /api/peers с JSON { publicKey }, обновление списка.
Ошибки отображаются в соответствующем окне или строке, операции блокируют
повторную отправку. Закрытие окна во время создания заблокировано.

## Доступность и адаптивность

Modal имеет доступное название, переносит и удерживает фокус внутри,
возвращает фокус при закрытии и обрабатывает Escape, когда нет отправки.
IconButton имеет aria-label и title, SVG скрыт от скринридера.
На мобильных список становится карточками, окно ограничено высотой экрана
и прокручивается; длинные ссылки и ключи не расширяют страницу.

## Тема и публичная страница

Единственный источник токенов: packages/web/public/assets/theme.css.
Он содержит цвета, поверхности, шрифты, отступы, радиусы, тени.
Админка подключает тему из index.html; CSS Modules используют переменные темы.
Минимальные глобальные reset-стили остаются отдельно от стилей компонентов.
packages/web/public/assets/setup.css использует ту же тему и стилизует текущую
публичную HTML-разметку body/main/.icon/h1/p/form/button/small.
Vite копирует оба файла в dist/assets с постоянными именами.
Публичный HTML должен подключать только /assets/theme.css и /assets/setup.css,
без React, административного JS и встроенного CSS.

## Зависимости от C++ (не реализуются этой задачей)

1. POST /api/peers должен читать, проверять и сохранять name. Сейчас тело
   игнорируется; фронтенд не должен подменять имя локальными данными.
   Ответ должен сохранять publicKey; privateKey клиенту не требуется.
2. Публичный HTTP-сервер должен отдавать оба CSS-файла из /app/web/assets
   и подключать их в /setup/:token, удалив встроенный style. Сейчас mount
   /app/web зарегистрирован только на административном сервере.
3. Оба изменения явно описать в документации пакета и итоговом отчёте.

## Проверки

Обновить тестовые ответы под реальный C++ контракт. Проверить список,
handshake-границы, обновление, создание и выпуск ссылки, повтор выпуска после
ошибки без повторного создания, копирование, подтверждение удаления и ошибки.
Проверить доступность и закрытие модальных окон, существующую авторизацию.
Запустить typecheck, все frontend-тесты, production build. Проверить наличие
обоих публичных CSS-файлов в dist и отсутствие административного JS в них.
Новые зависимости, коммиты и изменения C++ не требуются.
